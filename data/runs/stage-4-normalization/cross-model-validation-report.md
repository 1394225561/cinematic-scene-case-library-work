# 阶段 4：语料规范化与跨模型验证报告

生成日期：2026-08-16

## 1. 结论

`cinematic-scene-case-library` 可以作为模型无关的通用案例库存在，但必须采用“一个模型中性场景表示 + 多个模型适配器”的结构，不能把任一模型的最终 Prompt 语法当作通用语法。

三个样本均成功转换为：

1. 可追溯的来源层
2. 独立的素材引用层
3. 模型无关场景层
4. 合法的 Seedance 2.0 文本验证稿
5. 合法的 MiniMax H3 T2VA 文本验证稿

本轮没有图片、视频或音频输入。因此，两个适配层都使用纯文本描述：Seedance 不激活 `@tag`，H3 不创建 `<Picture N>`、`<Subject N>`、`<Video N>` 或 `<Audio N>`。实际工作中一旦用户提供真实媒体，适配器必须按媒体的真实用途重新选择和绑定模型语法。

## 3. 五层边界

| 层 | 保存内容 | 禁止内容 |
|---|---|---|
| 来源层 | Prompt 哈希、完整源记录指针、文件夹、资产元数据、原始设置、来源冲突 | 覆盖或修正原文；把重复生成次数当质量 |
| 素材引用层 | 角色、地点、变身、道具的源标签和可移植描述 | 未提供媒体时激活模型引用标签 |
| 模型无关场景层 | 目标、主体、空间、动作因果、表演、摄影结果、物理、光线、声音、连续性、约束 | `@tag`、Context-IR、模型任务名和平台专有设置 |
| Seedance 适配层 | 首帧占位、屏幕方向、空间阻挡、镜头段落、局部失败锁、Seedance 可读时间线 | 伪造 `@tag`；携带 H3 标签或字段 |
| H3 适配层 | Prompt Mode、Runtime Task、Context-IR 三字段、严格切点、说话人 ID、`<d>` | 把 Seedance 标签改名为 H3 媒体；把运行设置塞入 Prompt |

## 4. 可迁移字段

以下信息在 Seedance 与 H3 中都能稳定保留：

- 当前镜头或序列的可见目标
- 主体身份的文本锚点和当前状态
- 屏幕位置、相对尺度、朝向、视线和地标关系
- 动作的准备、接触、受力、结果和反应
- 表演目标、节拍、微动作、说话方式和精确台词
- 构图结果、视点、镜头运动结果和光学观感
- 重量、摩擦、惯性、碰撞、材料反应和环境物理
- 光源方向、曝光关系、色彩组织和大气层次
- 环境声、动作声、对白、静默和音乐规则
- 跨切点的空间、状态、光线、损伤和道具连续性

这些字段构成案例库应保存的“通用场景范式”。

## 5. 必须适配的字段

### Seedance

- 使用当前平台真实存在的 `@tag`，不能从源 Prompt 的 `<<<...>>>` 或 UUID 猜造。
- 对首帧人物占位、左右关系、视线、身体方向和地标距离做前置锁定。
- 单镜头和多镜头使用 Seedance 的分节式导演结构；局部失败锁紧邻其保护内容。
- 时长、画幅、模式等若由界面控制，正式 Prompt 可省略，但案例记录必须保留其来源。

### MiniMax H3

- 没有真实媒体时使用 T2VA；源 Prompt 本身不是媒体引用。
- 真实首帧、尾帧或其他媒体出现时，按实际角色选择 I2VA、L2VA、FL2VA 或 Ref2VA。
- 只有真实可访问媒体才能绑定 `<Picture N>`、`<Subject N>`、`<Video N>` 和 `<Audio N>`。
- Base 模式严格使用 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。
- 说话人使用稳定 `(Sx)`，原语言对白逐字写入 `<d>[Language]>`。
- 运行时长、画幅和任务值保存在 H3 SETTINGS，不混入 Context-IR Prompt。
- 单次生成必须在 4 至 15 秒内；更长内容必须切为多个生成单元。

## 6. 三个样本的关键判断

### 对白表演

对白内容、语气、微动作、机位侧向、实际光源和声音均可完整迁移。Seedance 通过时间段和局部口型锁表达；H3 通过 `(S1)` 与 `<d>[English] Are you kidding me?</d>` 表达。源 Prompt 中的摄影师姓名、硬件品牌堆叠、8K/IMAX 和皮肤渲染形容不属于必要场景语义，已作为可审计压缩项记录。

### 动作打斗

原文的动作因果链优秀，但约 14 个切分段在 10 秒声明内过载，且与全部资产的 15 秒元数据冲突。用户批准采用 15 秒，并压缩为五个节拍：格挡、卸力反击、闪避借力、上勾拳与坠地、起身与对白。两种模型都保留左右关系、体型差、受力、速度切换、环境完整性和日语台词。五节拍是适配决策，不是对原 Prompt 结构的重新陈述。

H3 版本已经使用单次允许的 15 秒上限，不允许再追加动作或对白。若后续案例需要更长恢复、反应或下一轮战斗，应拆分生成并建立出入状态锁。

### 环境建立

最初候选要求在 6 秒内从约 150 米缓慢下降到街面，距离与速度互相冲突，未被静默修正。用户批准改用 10 秒静态高空样本。新样本证明环境建立不依赖相机移动：暴雨深度层、稀疏车辆、实景光源和一列高架列车足以形成持续内部运动。

10 秒来自全部 17 个资产元数据，而不是 Prompt 正文。两层来源保持分离。

## 7. 已知损失与验证边界

- 原始参考媒体未下载，因此无法验证人物面貌、服装细节、环境几何和材质是否与图片逐像素一致。
- 本轮验证的是 Prompt 结构、来源审计、模型语法和时序可执行性，不是实际生成视频的画面质量评测。
- Seedance 与 H3 的文本验证稿都可以直接作为无媒体 T2V/T2VA 输入；若实际工作带入用户资产，必须重新绑定引用并再次校验模式。
- 原作者重复生成同一 Prompt 的次数没有提供画面质量证据，仍不得用于精华案例评分。

## 9. 阶段结论

跨模型验证支持以下架构：案例库保存模型无关场景范式和来源审计，同时为每个目标模型保存适配规则或适配示例。它可以服务 Seedance、MiniMax H3 及后续模型，但新增模型必须拥有独立适配契约；不存在一个可以原样提交给所有视频模型的最终 Prompt。

本报告是阶段 4 审核产物。用户批准前，不批量规范化全部 7517 个唯一 Prompt，也不进入阶段 5。
